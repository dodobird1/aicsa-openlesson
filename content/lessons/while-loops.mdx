## 从 for 回到 while

第 11 课你学 for 时见过它的祖先。同一个「打印 1 到 5」，两种写法对照：

```java
// for 版：三要素集中在第一行
for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}

// while 版：三要素分散在三个地方
int i = 1;                  // 要素一：初始化——循环外
while (i <= 5) {            // 要素二：条件——每次进循环体前判断
    System.out.println(i);
    i++;                    // 要素三：更新——循环体内最后一行
}
```

功能完全等价。既然 for 更紧凑，为什么还要 while？因为它们各有一块主场：

- **for 的主场**：起点、终点、步长在开工前就都知道（打印 1 到 100、遍历字符串）；
- **while 的主场**：**不知道要循环几次**——循环到「某个条件第一次成立」为止。

## while 的主场：次数未知的循环

一个典型问题：从 1000 开始不断除以 2，要除几次才会小于 1？

```java
int value = 1000;
int steps = 0;
while (value >= 1) {
    value = value / 2;
    steps++;
}
System.out.println(steps);   // 10 次——事先真算不出来
```

这类「做到满足为止」的逻辑，写 for 反而别扭。另一个常用套路是**哨兵值**（sentinel）：用一个特殊值标记输入结束——AP 考纲不考键盘输入，但哨兵思想在题目里到处都是。

## 死循环：三要素检查法

while 的三要素分散在三个地方，任何一处缺失或写错，就是**死循环**（infinite loop）——条件永远为 true，程序永远转下去：

```java
int i = 0;
while (i < 3) {
    System.out.println(i);   // 忘了 i++：i 永远是 0，永远小于 3
}
```

写完 while 立刻做**三要素检查**：初始化有没有？条件里的变量在循环体内有没有被推进？推进的方向是不是朝着条件变 false 走（条件是 `i < 10` 却写 `i--`，同样死循环）？

<Callout title="考纲边界">do-while 循环不在 AP CSA 考纲内（CED 未收录），认识即可、不用练。AP 只考 for 和 while。</Callout>
