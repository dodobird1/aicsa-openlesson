## 数步数，不背术语

「程序 A 比 B 快吗？」——AP CSA 的考法（CED Topic 2.12）非常朴素：**数一算某条语句总共执行多少次**，再比大小。不需要 Big-O、不需要专业术语，只需要乘法和加法：

- 两个**顺序**的循环：次数**相加**（n + n = 2n）；
- **嵌套**的循环：次数**相乘**（n × n）；
- 内层**依赖**外层的嵌套：逐行累加（1 + 2 + … + n）。

## 三种形状，三种命运

用 n = 1000 感受差距：

| 形状 | 次数公式 | n = 1000 时 |
| --- | --- | --- |
| 单循环 | n | 1 千步 |
| 两个顺序循环 | n + n = 2n | 2 千步 |
| 嵌套循环 | n × n | 100 万步 |

顺序翻倍只是常数变化；嵌套平方是**量级**变化——n 从 1000 变 2000，单循环从 1000 步变 2000 步，嵌套从 100 万步变 400 万步。这就是「嵌套循环要警惕」的直觉来源。

## 依赖型嵌套：等差累加

嵌套循环一课的三角形（内层 j 从 1 到 i）：

```java
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= i; j++) {
        count++;          // 执行 1 + 2 + … + n 次
    }
}
```

n = 4 时是 1+2+3+4 = 10 次——不是 4×4=16。内层次数随行号变化时，**逐行累加，不能直接乘**。AP 不要求等差求和公式，n 小的时候老老实实加。

## 数次数的三个注意

1. **数循环体还是数整条语句**：AP 题会明确问「statement S 执行几次」，看准 S 是哪一行——循环体里的语句执行 n 次，循环头里的 `i++` 同样是 n 次（每轮体后执行一次）；真正执行 n+1 次的是条件判断，见下一条；
2. **别忘最后一轮的判断**：`i < n` 的判断执行 n+1 次（成功 n 次 + 失败退出 1 次）——题目专问条件判断时这是标准陷阱；
3. **嵌套先数内层**：内层一次完整跑多少，再乘外层次数。

## 每日一虫 🐛：数错的嵌套

看这段代码：

```java
int steps = 0;
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 4; j++) {
        steps++;
    }
}
System.out.println(steps);
```
