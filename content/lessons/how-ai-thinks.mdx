## 它不「知道」任何事

你平时用的 ChatGPT、Claude、DeepSeek 这类工具，底层叫**大语言模型**（Large Language Model, LLM）。它的工作原理一句话就能说清：**根据你给出的上文，预测下一个最可能出现的字，然后一个字一个字地把回答「吐」出来。**

它不是在数据库里查询答案，而是在做超大规模的「文字接龙」。这个原理决定了它的全部优点和缺点：

- **优点**：因为读过海量文本，它能在编程、写作、解释概念这些「语言密集」的任务上表现惊人；
- **缺点**：它没有「我不知道」的直觉。当它没把握时，它依然会流畅地、自信地、按正确格式继续接龙。

## 三个你必须知道的盲区

### 盲区一：幻觉（Hallucination）

AI 会**编造看起来完全可信的假信息**：不存在的论文、编造的 API 方法名、张冠李戴的引文。这不是它「坏」，而是接龙机制的自然结果——上文需要一个像样的答案，它就造一个像样的出来。

对学编程的你来说，最常见的幻觉是：**它推荐一个根本不存在的库函数，或者记错某个方法的行为**。比如把 `substring` 的参数含义记反，或者信誓旦旦地说某个类有某个方法——编译器会告诉你真相。

### 盲区二：知识截止（Knowledge Cutoff）

模型的训练数据有一个截止日期。截止日期之后的世界它一无所知（除非联网搜索）。问它「最新的 Java 版本特性」，它可能给你两年前的答案，而且态度同样自信。

### 盲区三：自信地错（Confidently Wrong）

AI 输出的「语气」和「正确性」完全不挂钩。它用同样流畅的口吻说出真理和谬误。所以**永远不要用「听起来很笃定」来判断一个 AI 回答是否可信**。

## 什么时候可以信它

一个实用的判断框架：

| 场景 | 信任程度 | 你的动作 |
| --- | --- | --- |
| 解释概念、换个说法讲一遍 | 高 | 直接用，有疑问再追问 |
| 讲解通用编程语法（for 循环、数组） | 较高 | 对照教材或运行代码验证 |
| 具体的 API 行为、方法名 | 中 | **必须验证**：查官方文档或直接跑代码 |
| 具体的事实、数字、论文、链接 | 低 | **必须交叉验证**：自己搜索核实 |
| 你的作业答案对不对 | 看情况 | 让它讲理由，用你自己的判断复核 |

记住这门课的黄金法则：**AI 负责解释，你负责验证。代码类的答案，编译和运行就是最好的验证。**
