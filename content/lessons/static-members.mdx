## 一份 vs 每人一份

上一课的虫揭示了 static 方法的边界。这课看 static 的**另一半**：static 变量。

画内存图就懂了。`new Dog()` 三次之后：

```text
Dog 类（图纸区）          对象区
┌──────────────┐        ┌────────────┐
│ dogsBorn = 3 │   ←──  │ a: name/age│
│  （仅此一份） │   ←──  | b: name/age|
└──────────────┘   ←──  | c: name/age|
                          └────────────┘
```

**实例变量**：每只狗一份（各自的 name、age）。**static 变量**：整个类只有一份，所有对象共享——它挂在图纸上，不挂在任何一只狗身上。

## 经典应用：对象计数器

```java
public class Dog {
    private String name;
    private static int dogsBorn = 0;    // 全类一份：出生计数

    public Dog(String n) {
        name = n;
        dogsBorn++;                     // 每造一只，共享计数 +1
    }

    public static int getDogsBorn() {
        return dogsBorn;                // static 方法读 static 变量：没问题
    }
}
```

new 三只狗之后，`Dog.getDogsBorn()` 是 **3**——不管你通过哪只狗去问（其实按惯例用类名问：`Dog.getDogsBorn()`）。

## static 方法：不需要对象的服务

你已经用了一个月的 static 方法：`Math.sqrt(25)`、`Math.random()`——**从没 new 过 Math**。因为它们不依赖任何对象的状态，答案对谁都一样，挂在整个类上即可。

这就解释了上一课的虫：static 方法运行时**没有「当前对象」**，所以摸不到实例变量——实例变量得先有对象才有归属。

## 判断口诀

> **要看对象状态（字段）的，用实例成员；跟具体对象无关的，用 static。**

| 场景 | 用什么 | 例 |
| --- | --- | --- |
| 读写字段 | 实例方法 | `getAge`、`birthday` |
| 全类统计、共享配置 | static 变量 | `dogsBorn` |
| 纯计算、工具函数 | static 方法 | `Math.sqrt`、`isEven` |

## 每日一虫 🐛：「我以为每只狗一份」

```java
public class Dog {
    private String name;
    private static int dogsBorn = 0;

    public Dog(String n) {
        name = n;
        dogsBorn++;
    }

    public int myNumber() {
        return dogsBorn;      // 想给每只狗发一个「出生编号」
    }
}
```
