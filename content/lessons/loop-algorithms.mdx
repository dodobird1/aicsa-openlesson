## 模板思维：认脸而非认题

AP 的循环题看起来千变万化，骨架只有五个。读题时先问：**这题在考哪个模板？**——认出模板，循环结构直接默写，只剩题目特有的条件要现想。

| 模板 | 骨架（核心三行） | 识别信号 |
| --- | --- | --- |
| 求和 sum | `int total = 0;` + 循环中 `total += x;` | 「计算……的总和／一共」 |
| 计数 count | `int count = 0;` + 命中时 `count++;` | 「有多少个……」 |
| 最值 max/min | `int max = 首个值;` + 更大则替换 | 「最大的／最小的」 |
| 查找 search | 循环中命中即处理（return 或记录） | 「第一个／是否存在」 |
| 条件统计 | count 模板 + if 条件 | 「满足……的有几个」 |

现在没有数组，我们用「1 到 n 的整数」和字符串当原料——模板学扎实了，Unit 4 换成数组只是换个容器。

## 求和与计数：最稳的两兄弟

```java
// 求和：1 到 100
int total = 0;
for (int n = 1; n <= 100; n++) {
    total += n;
}

// 计数：1 到 100 里有多少个 7 的倍数
int count = 0;
for (int n = 1; n <= 100; n++) {
    if (n % 7 == 0) {
        count++;
    }
}
```

两个模板共用一个铁律：**累加器必须在循环外声明并初始化**——放循环体内每轮都重新归零，累加永远只剩当前这一轮的数（而且循环结束后它根本不可见）。

## 最值：初值的学问

找最大值的模板有个著名陷阱——**初值**：

```java
int max = Integer.MIN_VALUE;   // 或直接用第一个元素（数组时代）
for (int n = 1; n <= 100; n++) {
    if (n > max) {
        max = n;
    }
}
```

初值取 `Integer.MIN_VALUE`（int 的理论最小值）。比它大的数都会替换它；若序列里的最大值正好就是这个最小值，初值本身已经是答案。初值取 `0` 才是虫：全负序列里没有数比 0 大，答案永远是 0——本课的每日一虫就是它。

## 查找：找到就收手

「找到第一个满足条件的数」——命中即用 `return` 离场，不要恋战：

```java
// 返回 1 到 n 中第一个 7 的倍数；不存在返回 -1（哨兵值惯例）
public static int firstMultipleOfSeven(int n) {
    for (int k = 1; k <= n; k++) {
        if (k % 7 == 0) {
            return k;      // 命中即走
        }
    }
    return -1;             // 全程未命中：哨兵值报告「没找到」
}
```

`return -1` 表示「不存在」——和 `indexOf` 找不到返回 −1 是同一个惯例，AP 两边都爱考。

## 每日一虫 🐛：永远打不过 0 的最大值

看这段代码：

```java
// 想找 -8、-3、-5 中最大的那个
int max = 0;
int a = -8, b = -3, c = -5;
if (a > max) { max = a; }
if (b > max) { max = b; }
if (c > max) { max = c; }
System.out.println(max);
```
