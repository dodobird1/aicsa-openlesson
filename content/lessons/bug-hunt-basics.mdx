## 为什么「找虫」是这门课的主线练习

选择题占全卷 55%，简答题占 45%。在选择题内部，权重最大的一项是**分析代码（Analyze Code）**：读别人的代码、预测它会做什么、找出错误。这一项约占选择题的 37–53%（官方 CED，2025 年秋季版，印刷页 146）。换到全卷大约是两成到三成。简答题要你自己写代码，那 45% 比分析代码在全卷里的份额更大。这一课练的找虫，是选择题里最大的一块；后面的项目和简答课负责写代码那 45%。

所以从这节课起，每节常规课都有一道「每日一虫」（Daily Bug）：一小段藏了一只虫的代码，你来抓（项目课用「抽查自查单」代替）。抓虫分三级：

- **L1 圈错行**：指出虫在哪一行、是什么类型（选择题，秒判）；
- **L2 说病根**：合上答案，用自己的话说清「为什么错、运行时会发生什么」；
- **L3 动手修**：修到编译通过、行为正确为止。

本课就是这套体系的第一课。先认识地形。

## 报错地形图：四大高频区

Java 编译器报错时不留情面，但报错信息本身就是地图。四大高频地形（你在 Hello World 里已经见过一部分）：

| 报错信息（第一行） | 病根 | 一句话口诀 |
| --- | --- | --- |
| `error: ';' expected` | 缺分号 | 句子要有句号 |
| `error: reached end of file while parsing` | 花括号不配对 | 有 `{` 必有 `}` |
| `error: cannot find symbol` | 变量/方法名拼错，或字符串没加引号 | 名字要对，文本要穿引号衣服 |
| `error: class X is public, should be declared in a file named X.java` | 类名和文件名不一致 | 类名 = 文件名，区分大小写 |

读报错的黄金习惯：**只看第一行和它指的行号**。后面的连锁报错往往是一个根因的回声——修好第一处，它们一起消失。

## 三步找虫法

拿到一段报错的代码，按这三步走，不要上来就乱改：

1. **定位**：读报错第一行 + 行号，锁定出错的大致位置；
2. **说病根**：先不动手，说出「这里是什么类型的错、为什么 Java 不接受」——能说清病根才算真找到，否则只是瞎蒙对了；
3. **最小修复**：只改必须改的那一处，改完立刻重新编译验证。

<Callout title="L2 为什么重要">直接跳到 L3「修好了」，你可能是蒙对的。说过一遍病根，下次同样的虫在 200 行代码里你才认得出它。这就是「每日一虫」坚持 L2 的原因。</Callout>

## 每日一虫 L1：圈出病根

```java
public class Counter {
    public static void main(String[] args) {
        int count = 0
        System.out.println(count);
    }
}
```

## 说病根：让导师检验你的 L2

找虫过程中最没把握的一个报错是哪个？把它发给苏格拉底导师——注意，它只会用提问引导你说出病根，不会直接告诉你答案。你自己的病根表述，就是这一关的作业。
