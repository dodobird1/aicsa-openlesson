     * Postcondition: votes 不被修改。
     */
    public String winner()
    { /* to be implemented */ }

## 官方风格评分标准（Scoring Guidelines）

**Question 7 — 共 5 分（单 part）**

### Canonical solution（标准答案，供对照）

```java
public String winner()
{
    String bestName = votes.get(0);
    int bestCount = 0;
    for (int i = 0; i < votes.size(); i++)
    {
        String name = votes.get(i);
        int count = 0;
        for (int j = 0; j < votes.size(); j++)
        {
            if (votes.get(j).equals(name))
            {
                count++;
            }
        }
        if (count > bestCount)
        {
            bestCount = count;
            bestName = name;
        }
    }
    return bestName;
}
```

### Scoring Criteria 与 Decision Rules

| # | Scoring Criteria | Decision Rules | 分 |
| --- | --- | --- | --- |
| 1 | 遍历 votes，访问每一个元素（外层候选循环） | 仍可得分：enhanced for 的等价形式 | 1 |
| 2 | 对每个候选统计其出现次数（内层**完整**遍历整张票列表） | 不得分：内层只从外层下标之后开始数（会把前面的票漏掉）；内层循环没有覆盖全部元素 | 1 |
| 3 | 比较票数并记录当前最高者（名字与票数同时更新） | 仍可得分：先收集每个候选的票数到辅助结构再找最大。不得分：只记票数没记名字，最后无法返回名字 | 1 |
| 4 | 返回得票最多的**名字**（不是票数）** (algorithm)** | 不得分：返回票数；返回 null；votes 被修改（remove/set 等——违反 postcondition，属「修改持久数据」）；并列处理破坏 precondition 假设而引入错误 | 1 |
| 5 | 算法整体正确：对 precondition 保证的任意输入（唯一胜者）返回正确结果 **(algorithm)** | 不得分：串联的两层逻辑组装错误（如比较用的票数与记录的名字不同步）；初始化缺失导致首候选永远或从不入选。仍可得分：用「把每个名字去重收进新列表再统计」的等价策略（新列表是本地对象，不违反 postcondition） | 1 |
| | **Total** | | **5** |

**Scoring Notes**：precondition 保证唯一胜者，因此比较用严格 `>` 即可，**不需要**也不应该写并列分支；`bestCount` 初值取 0 配合严格 `>` 是安全的（胜者票数至少为 1）。若学生把「去重列表」作为辅助，注意其必须建在本地（new 出来的），否则触碰 postcondition。
