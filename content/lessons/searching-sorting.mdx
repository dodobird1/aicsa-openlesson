## 查找：从翻字典说起

**线性查找**（linear search）：从头翻到尾，见到目标就收——你已经会了（Unit 2 的查找模板）：

```java
public static int linearSearch(int[] a, int target) {
    for (int i = 0; i < a.length; i++) {
        if (a[i] == target) {
            return i;
        }
    }
    return -1;
}
```

它对**任何**数组都有效，最坏要翻 n 次。但字典为什么从中间翻开？因为字典**有序**——这引出了魔法版查找。

## 二分查找：折半、再折半

**二分查找**（binary search）的前提只有一条：**数组有序**。流程：

1. 看中间元素：等于目标 → 找到；大于目标 → 目标只在**左半**；小于 → 只在**右半**；
2. 把搜索范围砍掉一半，重复。

```java
int low = 0;
int high = a.length - 1;
while (low <= high) {
    int mid = (low + high) / 2;
    if (a[mid] == target) {
        return mid;           // 找到
    } else if (a[mid] < target) {
        low = mid + 1;        // 目标在右半
    } else {
        high = mid - 1;       // 目标在左半
    }
}
return -1;                    // 区间空了：不存在
```

威力感受：用上面这段 `while (low <= high)`，最坏情况要比较 floor(log2(n)) + 1 次。在 1 到 8 里找任意数，最多 **4 次**（范围大约还剩 8、4、2、1 时各比一次）；在 1 到 16 里最多 **5 次**；在 1000 个有序数里，最多 **10 次**。只数「砍了几刀」（8 → 4 → 2 → 1 有 3 个箭头）会把最后剩下的那个元素漏掉。折半的杀伤力是指数级的：元素翻倍，次数只加一。

## 排序：三种必会的算法

CED 只考三种排序（CED 边界声明：其余排序一律不考）。

### 选择排序 selection sort —— 每轮选冠军放前排

每轮从未排序区挑**最小**的，与未排序区第一个交换：

```text
原数组:      [5, 2, 8, 1]
第 1 轮后:   [1, 2, 8, 5]    ← 最小值 1 与下标 0 的 5 交换
```

注意第 1 轮后是 `[1, 2, 8, 5]`——2 恰好还在原位（它没动，是 1 和 5 交换了）。**「一轮之后长什么样」是 MCQ 的标准问法**，老老实实模拟交换。

### 插入排序 insertion sort —— 理扑克牌

把每个新元素**插进**前面已排好的队伍里（从后往前挪位置）：

```text
原数组:      [5, 2, 8, 1]
处理 2 之后: [2, 5, 8, 1]    ← 2 插到 5 前面
处理 8 之后: [2, 5, 8, 1]    ← 8 比 5 大，原地不动
处理 1 之后: [1, 2, 5, 8]    ← 1 插到最前
```

### 归并排序 merge sort —— 分半、各排、合并

递归地把数组对半拆到单个元素（天然有序），再把两段有序的**合并**成一段。细节的递归机制在后面的「递归」一课讲（中间还要先学二维数组），本课要求：**看得懂合并的过程**——两段各拿一个指针，谁小谁先入选。

## 每日一虫 🐛：忘了「有序」这个前提

```java
int[] a = {9, 3, 7, 1};      // 注意：无序！
// 用二分查找找 1
int low = 0, high = 3;
while (low <= high) {
    int mid = (low + high) / 2;
    if (a[mid] == 1) { System.out.println("找到了"); break; }
    else if (a[mid] < 1) { low = mid + 1; }
    else { high = mid - 1; }
}
```
