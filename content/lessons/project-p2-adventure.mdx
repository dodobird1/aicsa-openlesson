## P2 是什么

一个**文字冒险游戏**（text adventure）：玩家在 20 个房间里探索，每个房间有描述、有岔路（向北？向东？）、有事件（捡到钥匙、遇到守卫）。整个游戏跑在一个 `while` 主循环里，每个房间用 `if / else if` 分发——**Unit 2 的每个知识点都在这个项目里有一份工作**。

和 P1 的区别：P1 判断一张卡片并打印对错；P2 用 `while` 把许多房间串成能玩的一局。

## 指挥五步·完整版

P1 你用了简化版流程。P2 起用完整版，每步都到位：

1. **画地图**：动手写代码之前先画——纸笔或画图工具都行，房间画成方框、箭头连线。20 个房间的地图先画出来，你才知道每个房间通向哪；
2. **写规格书**：每个房间一行规格：描述一句话、有哪些出口、进入时发生什么事件；
3. **手写核心框架**：主循环 `while` + 房间分发 `if/else if` 骨架——这部分**必须你亲手写**，它是项目的心脏；
4. **逐房实现**：一个房间一个方法（`visitRoom1()`、`visitRoom2()`……），照规格书填内容，AI 教练只审查不代写；
5. **互玩测试**：让一个同学玩你的游戏，记录他遇到的 bug 和他觉得「看不懂」的地方——这是最真实的验收。

## 先画后写：地图长什么样

起步版 6 个房间的地图示意（箭头是可通行的方向）：

```text
[1 入口] --北--> [2 走廊] --东--> [3 图书室]
                    |南                |
                  [4 储藏室] --西--> [5 暗道] --北--> [6 出口]
```

每个房间一行规格书，示例：

- **房间 3（图书室）**：描述「书架间飘着灰」。出口：西（回走廊）。事件：第一次进入捡到钥匙（`hasKey` 变为 true）。

注意 `hasKey` 这种**跨房间的状态**——它就是 P1 里「模拟用户输入」那类变量的升级版：游戏的世界状态。

<Disclosure title="时间紧？最低裁剪版与加难版">

- **最低版**（约 1 小时）：3 个房间 + while 主循环 + 一个 hasKey 事件，跑通一条完整路线即达标；
- **标准版**：6–8 个房间，至少一条死路和一把钥匙；
- **加难版**（寒假可选）：把「模拟玩家选择」升级成真实输入；或加入金币计数、步数限制。项目进度永远让位于当周课程：**课 > 虫 > 项目**。

</Disclosure>

## 验收与抽查

1. **跑通**：至少一条从入口到出口的完整路线能玩；
2. **互玩记录**：一位同学试玩，记下 2 个 bug、1 条「看不懂」——全修掉；
3. **抽查讲解**：随机指一个房间的方法，向同学或家长逐行讲清：这个方法改了哪些状态、为什么用 if 而不是别的。讲不清的地方回课重学。

<Callout title="放下 AI · 项目复盘">关掉结对教练，写五行复盘（记进错题本）：1) 这次指挥五步里最省时间的是哪步？2) 最想跳过却最有用的是哪步？3) 我的 while 主循环退出条件靠什么变量？4) if/else if 分发链的顺序重要吗，为什么？5) 下个项目我想提前做对的一件事。写完，Unit 2 只剩两课：红队日和检测卷。</Callout>
