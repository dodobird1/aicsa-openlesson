## 上一课埋的雷，今天正式引爆

删除后元素**集体左移**——那么「边遍历边删除」会发生什么？先看事故现场：

```java
// 意图：删除列表里所有的 4
ArrayList<Integer> list = new ArrayList<Integer>();
list.add(2);
list.add(4);
list.add(4);      // list = [2, 4, 4]

for (int i = 0; i < list.size(); i++) {
    if (list.get(i) == 4) {
        list.remove(i);
    }
}
```

逐步追踪（条件里的 size 是**动态**的，每轮重新读）：

| 轮次 | i | 状态 | 发生什么 |
| --- | --- | --- | --- |
| 1 | 0 | [2, 4, 4] | 元素 2 不是 4，跳过 |
| 2 | 1 | [2, 4, 4] | 是 4，删除 → [2, 4]，**第二个 4 左移到下标 1** |
| 3 | 2 | [2, 4] | 2 >= size(2)，循环结束——**下标 1 的 4 成了漏网之鱼** |

最终 `[2, 4]`——**漏删一个**。如果条件写成固定的旧长度还会越界崩溃。病根一句话：**删除后 i 停在原地，但元素左移了一位——i++ 一走，就跳过了刚补位上来的元素**。

## 解法：倒序遍历

**从尾往头删，左移就伤不到你**——删掉后面的元素，前面的下标纹丝不动：

```java
for (int i = list.size() - 1; i >= 0; i--) {
    if (list.get(i) == 4) {
        list.remove(i);
    }
}
```

倒序时被删元素右边的都在已处理区，左移只影响右侧——安稳。这段骨架请整段默写，它是 FRQ Q3 的高频构件。

<Callout title="考纲边界">遍历 ArrayList 时增删元素的另一条安全路是新建列表（把想留的抄过去）。AP 两种都认，但**倒序删除是考场上的标准答案**——Quick Reference 只给 API 不给算法，这段骨架要靠平时默写进肌肉记忆。另外，用 for-each 遍历 ArrayList 时增删元素通常会抛 ConcurrentModificationException；碰巧删到末尾的元素时可能安静结束、不报错，但结果照样是错的。记住「for-each 只读」铁律。</Callout>

## 每日一虫 🐛：正序删除的三宗罪

上面的正序删除已经看到一宗罪（漏删）。完整的三宗罪：

1. **漏删**：相邻的目标元素只删到一个；
2. **越界**：若条件用固定长度（比如先存了 int n = list.size()），删到后面 i 冲出缩短后的列表；
3. **假象**：某些数据（目标元素不相邻）下恰好正确——虫在测试里隐身，考场上爆发。

## Q3 题型解剖

FRQ 第三题（Data Analysis with ArrayList，5 分）的固定长相：**给一个类，类里有个 ArrayList 字段，让你写方法处理它**。骨架示例：

```java
public class Gradebook {
    private ArrayList<Integer> scores;      // 题目给的字段

    public Gradebook() {                    // 题目给的构造器
        scores = new ArrayList<Integer>();
    }

    // 题目让你写的方法，比如：
    public int countAbove(int limit) { ... }        // 遍历统计
    public void dropBelow(int limit) { ... }        // 倒序删除
}
```

Q3 的三个识别信号：方法**操作字段里的列表**、不需要 new 新对象、遍历骨架直接上。你已具备全部零件——现在把它们组装成方法。
