## 后两题：数据的战场

## Q3 真题风格示例

> 给定类 Gradebook，含 `private ArrayList<Integer> scores` 字段（已初始化）。实现：
>
> - `public int countAbove(int limit)`：返回大于 limit 的成绩个数；
> - `public void dropBelow(int limit)`：从列表中删除所有严格小于 limit 的成绩。

**countAbove**（遍历统计——第 21 课模板）：

```java
public int countAbove(int limit) {
    int count = 0;
    for (int i = 0; i < scores.size(); i++) {
        if (scores.get(i) > limit) {
            count++;
        }
    }
    return count;
}
```

**dropBelow**（倒序删除——第 36 课七行骨架）：

```java
public void dropBelow(int limit) {
    for (int i = scores.size() - 1; i >= 0; i--) {
        if (scores.get(i) < limit) {
            scores.remove(i);
        }
    }
}
```

注意 Q3 的固定姿势：**方法操作的是字段 scores**——不 new 新列表、不改签名。

## Q4 真题风格示例

> 给定类 Grid，含 `private int[][] cells` 字段（已初始化）。实现：
>
> `public int maxInRow(int row)`：返回第 row 行的最大元素。

```java
public int maxInRow(int row) {
    int max = cells[row][0];                 // 擂主 = 该行第一个（真实元素，负数不怕）
    for (int col = 1; col < cells[row].length; col++) {
        if (cells[row][col] > max) {
            max = cells[row][col];
        }
    }
    return max;
}
```

行内最值 = 行最值模板 + `cells[row]` 这一行的一维化——上一课的 `grid[row].length` 思想直接复用。

## 部分分的艺术

FRQ 按点给分，**每一分都能单独挣**：

1. **写不出完整逻辑，先写遍历骨架**：循环头（条件用对 length/size）本身就可能踩中一个 non-algorithm 点；
2. **签名照抄题面**：方法头一个字符都不改（官方规则：改写了给定方法头的参数个数或类型，这道方法的 algorithm 点不给——一题里最大的分就没了。就算改了头，其他不靠这段算法的点仍按各点单独判分，方法别空着）；
3. **变量名表意**：row、col、count 这种自解释命名，阅卷人看得懂，心情也好；
4. **不确定就写两版**？不要——写一版最稳的（倒序删除、擂主初值 a[0]），别在考场发明新算法。

<Callout title="评分规则彩蛋">阅卷的 Errors to Ignore 清单相当宽容：可推断的拼写、局部变量忘声明、缺分号、= 与 == 笔误（阅卷按意图理解）都不扣分。**真正扣分的是逻辑错**：边界错、忘更新、条件反了。所以考场策略：把逻辑写清楚，别为一个分号慌张。</Callout>
