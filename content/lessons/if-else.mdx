## 程序的第一个岔路口

到目前为止，你的程序都是「一条道走到黑」——从 main 第一行执行到最后一行。`if` 让程序第一次拥有**岔路**：

```java
int score = 85;
if (score >= 60) {
    System.out.println("及格");
} else {
    System.out.println("不及格");
}
```

解剖一下：

- `if (条件)` —— 括号里必须是一个 **boolean 表达式**（上一课的成果在这里落地）；
- 条件为 true → 执行 if 的花括号体；
- 条件为 false → 跳过它，执行 `else` 的花括号体（else 可省略）。

## else if 链：顺序就是逻辑

多个区间判断用 `else if` 串起来——成绩分级是标准例子：

```java
if (score >= 90) {
    grade = "A";
} else if (score >= 80) {
    grade = "B";
} else if (score >= 60) {
    grade = "C";
} else {
    grade = "F";
}
```

`else if` 的隐含前提是「前面的条件都不成立」。所以 score = 85 走到 `score >= 80` 时，已经隐含「不满足 ≥ 90」——不需要写 `score >= 80 && score < 90`。

**顺序就是逻辑**：把 `score >= 60` 写在最前面，后面的分支全部不可达——这是本课虫的主角。

## 嵌套 if 与悬空 else

if 里面可以再放 if（嵌套）。但省略花括号时，`else` 永远属于**离它最近的那个 if**——叫悬空 else（dangling else）：

```java
if (x > 5)
    if (x > 20)
        System.out.println("big");
else
    System.out.println("small");   // 这个 else 属于内层 if！缩进是骗人的
```

防御方法只有一条：**永远写花括号**，哪怕体里只有一行。这门课从头到尾都这么写，AP 阅卷也完全不扣花括号。

## 每日一虫 🐛：单等号遇上 boolean

上一课说过 `if (x = 5)` 对 int 是编译错误——安全的。但对 boolean 是**合法的灾难**：

```java
boolean isReady = true;
if (isReady = false) {          // 虫在这：单等号是赋值
    System.out.println("go");
} else {
    System.out.println("wait");
}
```
