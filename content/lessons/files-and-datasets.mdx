## 考纲新大陆：程序之外的数据

到目前为止，你的所有数据都活在程序里——程序一停，数据消失。**文件**（file）让数据在程序之外长久存在。2025 修订版考纲新增了 Topic 4.6：**用 File 和 Scanner 类读文本文件**——本课拿下它。

## 读文件的标准骨架（背下来）

```java
import java.io.File;                    // File 和 IOException 在 java.io 包
import java.io.IOException;
import java.util.Scanner;               // Scanner 在 java.util 包

public class Reader {
    public static void main(String[] args) throws IOException {   // 处理「文件打不开」
        File file = new File("scores.txt");        // 按路径名拿文件对象
        Scanner in = new Scanner(file);            // 把 Scanner 接到文件上

        while (in.hasNext()) {                     // 还有下一个数据吗？
            int score = in.nextInt();              // 有就读一个
            System.out.println(score);
        }
        in.close();                                // 用完关闭
    }
}
```

五个考点全部在这段骨架里：

1. **import 两个包**：`java.io.File`、`java.io.IOException`（Scanner 是 `java.util.Scanner`）；
2. **方法头加 `throws IOException`**：文件可能打不开，Java 强制你表态；
3. **`while (in.hasNext())` 驱动循环**：还有数据就继续——和「次数未知的 while」天生一对；
4. **`nextInt()` 读整数**，同理 `nextDouble()`、`next()`（读一个词）、`nextLine()`（读整行）；
5. **`in.close()`** 收尾。

<Callout title="考纲边界">键盘输入（System.in）明确不考——Scanner 只以「读文件」的身份出场。nextLine 与其他 next 方法混用、分隔符的正则特性也不考。Quick Reference 上 Scanner 全家福：Scanner(File)、nextInt、nextDouble、nextBoolean、nextLine、next、hasNext、close。</Callout>

## 新增武器：split 拆行

一行里挤着多个数据怎么办？`split` 按分隔符把字符串拆成**字符串数组**（Quick Reference 新成员）：

```java
String line = "88,92,79";
String[] parts = line.split(",");     // ["88", "92", "79"]
int first = Integer.parseInt(parts[0]);   // 需要数字？parseInt 交给你
```

读文件（一行一条记录）+ split（一行拆多段）+ parseInt（字符串转数字）——三件套是数据集处理的完整流水线。
